# H3 舞蹈提示词质量实测

## 测试目标

固定用户输入：`一个亚洲女生在跳舞，真实世界，直播视角，周围有很多路过的大爷大妈奇怪地打量她。`。使用真实 ComfyUI `APS_H3PromptStudio`、LM 档案的 `qwen3.5-9b-uncensored-hauhaucs-aggressive`、`reasoning=high`、8 秒、不卸载模型，覆盖 I2VA、FL2VA、Ref2VA。图片批次只提供媒体数量；Ref2VA 最终验收另外连接了含明确窄角色的已分析 Manifest，未把假图片内容告诉模型。

质量门槛不是“越长越好”。成品必须：通过目标协议；用白描写出主体位置、动作起点、连续路径和结束；直播机位符合手持实拍；路人行为有空间和因果连续性；不靠“唯美、震撼、梦幻、电影感”等空洞修饰词；参考内容仅来自用户文字或已分析 Manifest。

## 基线与两份 Markdown

| 策略 | I2VA | FL2VA | Ref2VA | 结论 |
|---|---:|---:|---:|---|
| 原内置核心 | 失败 | 失败 | 失败 | 0/3；字段、镜头编号、summary 前缀在一次修复后仍错误 |
| 基础版 Markdown | 通过 | 失败 | 通过（5 warnings） | 2/3；动作仍偏概括，Ref2VA 对裸图脑补内容 |
| R2VA 加强版 Markdown | 失败 | 通过 | 通过（4 warnings） | 2/3；错误模式会诱导基础模式输出六段 Ref2VA；还会擅加 BGM |

两份 Markdown 包含有价值的参考角色分工、忠实改写与镜头检查，但全文直接加载会让 9B 在多个示例和模式间串格式。它们适合作为按任务显式选择的资料，不适合整体并入 Model Core。

## 本轮修复

- 模式层改为最小、可照抄的 I2VA / FL2VA / Ref2VA 骨架，明确首帧对齐行不是 Shot，Shot 1 不写时间戳。
- Model Core 增加白描要求：位置、动作起点、身体运动路径、物理结果、邻近人物反应、明确结尾；禁止没有可视事实的装饰性形容词。
- 允许未规定处补足小动作、环境声、镜头微调和自然反应，但不得替换主动作或制造无因果的群体状态跳变。
- 明确 H3 文本节点看不到裸图片像素；未分析图片只能承担模式规定的对齐角色。Ref2VA 对未分析图片声称具体保留内容会硬失败。
- 对小模型常见且无语义歧义的协议漂移做确定性归一：零时刻 Shot 1、紧凑秒数、偏移镜头编号、重复 I2VA 对齐句和残留模板占位符。
- Ref2VA 未知 `<Asset N>` 与非法 retention 行由 warning 提升为 error；高推理档案的修复轮降到 medium，降低双调用超时风险。

## 修复后实测输出

### I2VA

通过。成品正确首行引用 `<Picture 1>`，使用单镜头手持直播视角；女生从抬臂、转体、侧步形成连续舞蹈短句；大爷大妈边走边回头或短暂停顿；环境声为脚步、衣料与交通声；无 BGM。一次样本仍用了 `either finishes ... or pauses` 两可结尾，因此新增“成品必须选择一个明确结尾”的约束，尚未以另一轮 provider 调用单独证明该措辞完全消失。

### FL2VA

通过。首尾图片分别对齐 0.00 与 8.00 秒；动作从侧步、抬臂、摆胯推进到明确收势，镜头只做轻微手持跟随；背景人物动作连续，未抢主角；无 BGM。该样本是三种模式中最完整、最接近可直接生成的一份。

### Ref2VA

使用已分析 Manifest 单独重试后通过。`<Picture 1>` 只承担人物身份，`<Picture 2>` 只承担路人构图；正文不再虚构衣着或具体地点，写出一个 8 秒单镜头动作过程。仍有 350–500 词密度和 style opening 两项建议警告；对这个简单单镜头任务，约 150 词更紧凑，警告不应为了凑字数强行扩写。整组三连跑时一次超过档案 120 秒，说明 9B 的 Ref2VA 延迟仍有波动。

## 结论

更新后的结构已经能做到稳定的“可用初稿”，而不是一次完美导演稿。实测可交付样本为 I2VA、FL2VA、Ref2VA 各至少一份；结构成功率明显高于基线，且 FL2VA 质量最好。当前主要剩余风险是本地 9B 的随机超时与偶发模板化措辞，不应通过继续堆叠长系统提示词解决。实际使用 Ref2VA 时应先连接 Reference Analyzer 生成 Manifest；只接裸图时，节点会拒绝模型假装看见图片内容。
