# P4.1 Resilience and Recovery

> Historical implementation record. ADR 0007 keeps protocol-only retry, atomic
> Session commit, deterministic dependencies, and recovery seams, while removing the
> independent authorization, Semantic Critic, and creative repair branches below.

P4.1 keeps the P4 atomic-commit rule while making provider failures diagnosable.
Malformed H3 Plans and ChangeSets receive at most one non-destructive structured
retry. Failed attempts never mutate the stable Session; backend warnings and the
final error retain only a bounded raw excerpt.

`PromptSession.commit()` now accepts a `RecoveryJournal` interface and stages a
complete next Session before publishing either the journal entry or the in-memory
swap. Entries are keyed by Session and node instance, carry transaction/base/result
revision IDs, and reject stale branches. `MemoryRecoveryJournal` is an executable,
thread-safe reference implementation, not durable production persistence; P5 may
wire a workflow/backend store without changing the commit seam.

Impact Analysis now closes two contract examples deterministically. Adding a
positive image fact removes matching negative tokens while preserving unrelated
negatives. Changing H3 duration scales existing shot timestamps by the same ratio.
These Python-proven dependent changes are recorded in Revision provenance and do
not trigger an extra Semantic Critic. Revision and consistency results record the
actual bounded repair count.

REFINE authorization is also conditional. Python may approve only a minimal `set`
whose leaf is explicitly named in the user's instruction and whose proposal has no
dependency, invalidation, conflict, or structural operation. Every ambiguous or
higher-impact proposal retains the independent authorization call. The old Plan
Patch compatibility path and other zero-caller aliases were removed so ChangeSet is
the single production and test mutation contract.

Tests: `test_p41_resilience.py`, `test_recovery_journal.py`,
`test_phase2_transactions.py`, and production regressions in
`test_nodes_phase4.py` / `test_nodes_h3.py`.
